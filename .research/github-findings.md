## 一、先排除：三个"看着好但本项目明确不能要"的

| 被排除的想法 | 出处 | 为什么不能要 |
|---|---|---|
| **关联弧线上的流动光脉冲** | `Cohenjikan/shiyun` README："束状汇向银心，**沿弧涌动柔光脉冲**"；本项目 README L1143 | **需求原文明确禁止**："每两个公式之间不应该有那种橙黄色的亮点，互相传递这种东西是不该有的"。`verify-galaxy.mjs` 断言连线组 `Points` 数量恒为 0 |

## 三、最有价值的一条：给关联加"类型"

**出处**：`Jia-Yee/math-knowledge-graph`（22★，MIT）——中文数学知识图谱，覆盖小初高到研究级。
它的边类型分布：

```
relates_to 20,921 | prerequisite 15,790 | follows 14,295 | belongs_to 5,296
contains 1,513 | contributes_to 554 | depends_on 289 | influences 85
related_to 42 | proved_by 38
```

**本项目现状**：1620 条关联的格式是
```js
['cn-hodge', 'cn-standard', 0.90, '标准猜想蕴含 Hodge 猜想']
                            ↑ 权重        ↑ 自由文本，无机器可读类型
```
于是渲染层只能一视同仁 —— **"蕴含"和"同属某一族"画出来是同一条线**。

### 我做的两项检验（决定该不该推荐它）

**检验 1：类型是不是权重换了层皮？**（若是，就是冗余，不该加）
```
proved_by    n=147  均值 0.807  区间 [0.50, 1.00]
generalizes  n= 23  均值 0.852  区间 [0.62, 0.96]
implies      n= 62  均值 0.808  区间 [0.60, 0.95]
equivalent   n= 68  均值 0.795  区间 [0.40, 0.95]
analogy      n= 52  均值 0.776  区间 [0.55, 0.96]
same_field   n= 27  均值 0.693  区间 [0.44, 0.88]
contrast     n=  6  均值 0.660  区间 [0.48, 0.96]
全部         n=1620 均值 0.776
```
区间几乎完全重叠、均值只差 0.19 → **类型携带权重没有的信息**，值得加。

**检验 2：能不能脚本自动分类？**（决定成本）
```
用正则从现有中文理由里抽类型：
  覆盖率 33.0%（534/1620）
  多义     5.8%（94 条同时命中 ≥2 类，如「消解与 alteration 是证明的工具」= proved_by+tool_for）
  未命中  67.0%（1086 条，多为「都以 Fano 簇为对象」这类弱关联）
```
→ **不能全自动**。33% 可机器预填，67% 需要人工判定。这是一项**写作工程**，不是脚本活。

### 成本与收益
- **渲染成本低**：`links.js` 已有 `applyFocus(id)` 在做逐边 `setColors()`，按类型上色是同一条路径；线宽/虚线的改动也只在 `LineMaterial` 上
- **注意**：详情面板**已经**在显示第四条理由文本（`ui.js:676`）。所以收益不在"看得见理由"，而在**线本身能区分**、以及**能按类型筛选**
- 建议起步：只做 5 类（蕴含 / 等价 / 推广-特例 / 依赖 / 类比），别一次上 10 类

## 四、其余值得做的（按性价比排序）

### 1. 深链接（可分享状态）— `Cohenjikan/shiyun`
它的做法：`#a=<诗人id>` / `#p=<诗体>.<编号>`，面板上有 🔗 分享按钮，打开链接即重建那首诗并复位星空。

本项目**已具备全部前置条件**：`window.__nebula` 暴露了 `focusOn` / `setView` / `settings`（main.js:244）。
只需序列化 `{节点id, view, shape, coloring, 关键显示层}`。
**不要把相机四元数写进 URL** —— 窗口比例一变就失效，分享出去是坏的。

### 2. 路径查询「他们怎么联系上的」
**出处**：`reppertj/philosophical-graphiti`（8★）——"可视化两节点间最短路径诱导出的子图"，正好对上斯坦福哲学百科那种概念网络。
BFS 一遍 1620 条边是毫秒级；已有 `links.highlight(id)` 只要从"单个 id"扩成"一组 id"。
这是**唯一能回答一个项目现在答不了的问题**的功能。

### 3. 焦点+上下文（改掉全局压暗）
选中时按**图距离**衰减：1 跳正常、2 跳半亮、其余更暗（而不是现在的一刀切）。
让"局部结构"浮出来，同时不丢失全局感。图距离用一次 BFS 就有。

### 4. 社区发现 ⚠ 谨慎
`patrik-cihal/lean-graph`（54★）从 Lean4 抽定理依赖图。它提示：真实数学依赖图**结构极不均匀**（少数枢纽 + 大量叶子）。
本项目 `field` 已经是人工的领域划分，自动社区检测**很可能与它冲突**，得到两套互不相容的分组。建议**先跑一次 Louvain 看看是否与 `field` 吻合**再决定，别直接上。

### 5. 语义缩放 ZMLT — **不建议**
`cns-iu/map4sci`（4★，ZMLT 论文实现，边带 `level` 1–7，随缩放换拓扑）技术上是这批里最精巧的。
但它**直接违反本项目的硬不变量**："半径 ← 重要度"必须对所有形态稳定、秩相关 −0.99。按缩放层级重建拓扑会让节点位置跳动。
记下来，但不做。

## 四之补、对一份并行调研报告的裁定

另一路调研（读 README + 源码，不读本项目）给了 6 个仓库的机制级细节和一份 TOP 5。
机制细节**很有价值**，但它的 TOP 5 是在**不知道本项目约束**的前提下排的，
逐条回代码核实后，**5 条里有 2 条必须否决、1 条已被部分实现**：

| 它的排名 | 主张 | 核实结果 |
|---|---|---|
| **#1** LOD 标签剔除（`min-zoomed-font-size: 8`） | 按投射屏幕尺寸隐藏 Sprite | ⚠ **半已实现**。`scene.js:934` 已有 `GLYPH.depthFade`：按 `camPos.distanceTo(s.position)` 把亮度压到 0.66。但那是**亮度衰减，不是可见性剔除** —— 确实没有 `visible=false` 的阈值。**可做，但不是"几行"**：本项目字高在整盘视角下**中位仅 8.0px**（README L991），阈值若取 8 会把一半公式直接抹掉。要按**机位**分别设阈值才安全 |
| **#4** 沿弧飞行的方向粒子 | "live particle count ≤ ~20，很划算" | ❌ **必须否决**。这是需求原文禁止的："不应该有那种橙黄色的亮点，互相传递这种东西是不该有的"（README L1143）。而且 `verify-galaxy.mjs` 有**硬断言**：`pointsInLinks === 0`，不通过就打印"仍有光点"并失败。它的"particle 数很少"论证在技术上对，但**这个功能被明确拒绝过** |
| **#5** 星团改用径向弹簧 | 用 `r += (targetR − r)·k` 替代一次性装填 | ⚠ **前提不成立**。本项目星团**本来就是"目标半径 + 抖动"**（`graph.js`：`n.sphR = clamp(n.clusterRadiusTarget + radJit, …)`），不是一次性装填，也没有力模拟。弹簧解决的是"需要重新装填"的问题 —— 而 `rebuildLayout()` 重排 59 个点是毫秒级。**没有要解决的问题**。另外它的 `targetRadius` 依赖 `degree`，而本项目的球心距只由**重要度**决定（Spearman 0.9931），引入 degree 会污染这条语义 |
| #2 强调预算（top-10% 权重特殊对待） | 一个阈值同时管粒子/辉光/标签/线宽 | ✓ **想法好，但与 #4 绑定**。本项目权重中位 0.80、`implies`/`proved_by` 均值 0.81 —— top-10% 大约就是"蕴含+推广"那一小撮。**若配合第三部分的"关系类型"一起做**，它才有意义（按类型而非分位数更可解释） |
| #3 拖拽 + 钉住的生命周期 | `dragfree→lock`、`layoutstop→unlock`、`mouseover→unlock` | ✓ **真实空白**。核实：`scene.js` 里的 `dragging` 是**拖拽旋转相机**（L681 `dragging = true` 后 L710 `moved >= 8` 判定点击 vs 拖拽），**没有任何节点级拖拽**。它的"解析布局下只需存一个相对解析槽位的世界偏移"是对的，不需要力模拟 |

**它另有 6 条本报告没提到、且核实为真的空白**（都有代码依据）：

1. **零导出功能** —— `toDataURL`/`toBlob`/`download`/`a.click` 全为 0（46 个 `export` 都是 ES module 语句）。`lean-graph` 的 7 点箭头多边形 SVG 导出可直接借用：本项目 464 个公式**已经是 canvas 纹理**，导出时天然可复用
2. **`camera.setViewOffset()` 代替偏移 `controls.target`** —— 本项目 `panelShiftAt()` 是在算一个世界坐标偏移去挪瞄准点，**会歪斜轨道**；`setViewOffset` 只挪投影中心、不动相机
3. **搜索只有子串匹配** —— `ui.js:516` `runSearch` 用 `toLowerCase().includes()`。`juggl` 的查询语言（`family:scheme importance:>0.9 -tag:modern`）是**真升级**而非重复
4. **一次性 draw call 的多层粒子 + 位掩码开关**（`beltoforion`）—— 本项目背景星云/深空星点等是**分开的 `THREE.Points`**；合成一个 `POINTS` + 整数 uniform 做层开关，切显示层可做到**零额外 draw call**
5. **形状编码节点种类**（`lean-graph`：定理五边形/定义三角/公理圆，同一外接圆半径）—— 与颜色**正交**的第二通道，且**灰度下和小尺寸下比色点更可读**。本项目状态用的是色点
6. **沿依赖边传播的颜色**（`lean-graph` `color_nodes()`，Kahn 拓扑排序 + `color_loss` 0.5 累加）—— 节点色相 = 所依赖之物色相的混合。可作为**第五种着色模式**，与现有 OKLab 族色正交

> 它的"反 CDF 采样"（beltoforion）核实后**优先级低**：本项目背景星云已用指数盘分布（`nebula.js:91` 注释"半径：指数盘分布（中心密、外缘稀）"），核心亮+长尾的效果已经有了。

**裁定结论**：它的价值在**机制细节**（箭头沿弧定位并按端点半径钳制、粒子几何体按宽度/颜色 intern、`setViewOffset` 的阻尼写法），不在**排序**。排序必须回项目约束重做。

## 五、一句话总结

这份清单里**真正的信息**是：本项目已经从两个命名灵感里吸收了骨架层最好的东西，剩下的高价值空白**不在视觉，在语义** —— 关联只有权重没有类型、状态无法分享、联系无法追溯。三个里最该先做的是**关系类型学**，因为它补的是"联系的种类"，而"联系"正是这个项目的主题。

一个方法论上的教训：两路调研都倾向于推荐"看起来很酷的视觉增强"（粒子、密度波、语义缩放），
但**回本项目核实后，最该做的三条全是语义/信息层的，不是视觉层的**。
原因在于本项目的视觉已经调得非常紧（秩相关 −0.99、厚径比 0.024、旋臂 CV 0.007、
亮度封顶 1.42 有明确理由）—— 任何视觉改动都在**破坏已有不变量**，
而语义层的空白是纯增量，不碰任何现有约束。

# 自进化目标 · Evolution Goal

> 这份文件定义**什么算「更好」**。没有它，自进化循环只是在改文件。
>
> 配套：`docs/EVOLUTION_LOOP.md`（每轮怎么转）、`scripts/score.mjs`（当前得分）。

---

## 一、北极星

**一句话**：让人打开得快、看得清、且我们说的每句话都能被验证。

拆成四条主线，任一退化都算失败：

| 维度 | 现在 | 目标 | 为什么重要 |
|---|---|---|---|
| **快** | 主包 2.3 MB gzip，首屏烘焙 4306 个公式 | 主包 ≤ 1.0 MB，首屏只烘焙可见 | 首屏是用户唯一一次机会 |
| **轻** | 数据占主包 82% | 数据按需加载 | 82% 的下载量在等一张自己没看的图 |
| **可信** | 存在假绿断言（标签说的比检查的多） | 零假绿，每个检查器有负向对照 | 从没失败过的检查器 = 不存在的检查器 |
| **稳** | 4 个测试文件 / 约 150 个模块 | 核心模块（graph/layout/query）有测试 | 改核心逻辑时没有安全网 |

## 二、达标清单（10 项）

每项都是**机器可验证**的，不是主观判断。`npm run score` 输出当前 `N/10`。

### 可信（先做，因为其余都依赖它）

- [ ] **G1 · source map 不公开部署**
  现状：线上 `billing-*.js.map` 等 8 个文件可被任何人下载（19 MB），等于公开源码。
  验证：`verify-assets` 断言 `dist/` 里没有 `.map`，或部署清单里不含。

- [ ] **G2 · 每个 verify 脚本有负向对照证明**
  现状：只有零星几个（`verify-assets`、`verify-readme-claims`）做过。
  要求：`docs/NEGATIVE-CONTROLS.md` 记录「故意破坏什么 → 检查器报什么错 → 恢复」。
  验证：该文档覆盖 `package.json` 里所有 `verify:*` / `check-*` 脚本，缺一个不得分。

### 快 / 轻

- [ ] **G3 · 主包 gzip ≤ 1500 KB**
  基线：2344 KB（实测线上传输）。

- [ ] **G4 · 主包 gzip ≤ 1000 KB**
  进阶目标。需要 G5 完成才可能达成。

- [ ] **G5 · 数据按需加载**
  现状：`src/graph.js` 静态 `import` 全部 15 个数据批次（6.0 MB 源码）。
  目标：首屏只同步加载手写核心（405 定理 + 59 猜想），其余 `fetch()` 后台补齐。
  验证：检查主 chunk 不含 `extra-*.js` / `*-extra.js` 的符号；且功能不退化。

- [ ] **G6 · 首屏只烘焙可见公式**
  现状：`splash` 等全部 4306 个公式烘焙完成才消失。
  目标：第一帧只烘焙视野内的，其余空闲补。
  验证：存在可测量的 `firstVisible` 指标，且 < 全量烘焙耗时。

- [ ] **G7 · TTI ≤ 15 秒**
  基线：真实浏览器未精确测量（headless 无 GPU 为 211 s，不可用作基线）。
  前提：先有可信测量（见 G6），否则本项不计分。

### 稳

- [ ] **G8 · `src/graph.js` 有单元测试**
  它产出 4306 节点 / 8747 关联，是全局最重要的纯函数，目前零单测。

- [ ] **G9 · `src/layout.js` 有单元测试**
  星云布局（旋臂、半径、去重叠）全靠 `check-*.mjs` 手工脚本兜，不在 CI。

- [ ] **G10 · lint warnings ≤ 200**
  现状 389。多数是 `no-unused-vars`，属可清理项。

## 三、护栏（任何一轮都不许破）

这些不是目标，是**底线**。破了必须当轮回滚。

1. `npm run ci` 必须 exit 0
2. `npm audit` 必须 0 漏洞
3. 线上站点 HTTP 200，且 `verify:live` 全过
4. 数据不丢：`check-data` 通过，节点/连线数不减少
5. 不删历史：归档而非删除，改动前留备份分支
6. **不许在无测量时声称改进**——没有前后对比就写「未测量」

## 四、每轮的操作流程

### 迭代期间（轻量，零浏览器）

只跑纯 Node 检查，秒级：

```bash
npm run score          # 当前 N/10
npm run ci             # 门禁
```

### 每轮收尾（重资源，**只跑一次**）

```bash
npm run verify:final   # 单线程、单次、跑完立即清理
```

`verify:final` 的硬性要求：

- **单进程串行**，不并行开多个浏览器
- 跑完**立即**杀掉所有 headless 进程
- 结束前断言残留进程数 = 0，否则非零退出
- 全程不超过 10 分钟，超时自杀

> 背景：无头浏览器会留下十几个进程，几轮就能吃满内存。
> 这不是建议，是硬约束——写进脚本里，不靠人记。

## 五、一轮的定义

**做完一件，验证，提交，记录。**

- 一轮只动**一个**达标项（G1–G10 之一）
- 改动前：`git branch backup/pre-<项>-<时间戳>`
- 改动后：`npm run score` 必须 ≥ 之前（不许为了一个指标牺牲另一个）
- 提交信息写明：改了什么、怎么验证的、分数从 N 到 M
- 更新 `docs/EVOLUTION_LOOP.md` 的债务清单

---

## 六、这个目标不做什么

- 不加新功能（ROADMAP 里的时间轴、多层级缩放等，等 G1–G10 全绿再说）
- 不为凑分数做无收益改动
- 不追 lint warning 数量本身（只追到 200，之后停）
- 不在没有可信测量前优化性能（先造尺子，再量）

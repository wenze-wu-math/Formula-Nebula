# 四方案改进记录（2026-11-02，针对用户四条反馈）

## 反馈 → 修复对照

### 1. A 方案（atlas）："缩小时太挤了，把行星缩放比例调小一点"

**根因**：`glyphScale(L)` 缩小时的公式是 `2^(L*0.5)`、下限 0.35 ——
L=-0.6 时 1 等星只缩到 81%（4.2px），而 3,027 颗星挤在 503px 的盘里。

**修法**（`designs/atlas/constants.js`）：指数 0.5 → **0.85**，下限 0.35 → 0.16。

| L | 改前半径 | 改后半径 |
|---:|---:|---:|
| -1.2 | 3.43px | 2.38px |
| -0.6 | 4.22px | 3.32px |
| 0 | 5.20px | 5.20px（不变，保住基准外观） |
| 0.6 | 5.70px | 5.70px（不受影响） |

### 2. A 方案："公式显示背景有 bug，颜色不一样"

**根因**：`bake.js` 的晕边位图是 64×64，用
`g.drawImage(haloPattern, 0, 0, W, H)` **整体拉伸**到每条公式的 W×H。

宽公式（W=400）横向拉伸 6.25 倍，窄公式（W=60）拉伸 0.94 倍 ——
边缘渐变带的像素宽度完全不同，叠在星空上就是"背景颜色不一样"。

**修法**：改成 **nine-slice（九宫格）**：四角原样贴、四边单向拉伸、
中心双向拉伸。边缘渐变带宽度恒定，所有公式的晕边一致
（新增 `drawHaloNineSlice()`，`designs/atlas/bake.js`）。

### 3. B 方案（map）："整个世界太小了，所有城市全挤一起了"

**根因有两个**（都修了）：

a) 世界 2000×1440 装不下 4,152 个地点（实测溢出到 2289×1588，
   中位最近邻只有 17.6 wu）。

   修法（`designs/map/src/constants.js`）：世界放大到 **3×**
   （6000×4320），同步放大 GRID_CELL（12）、SLOT_UNIT（510）、
   GRATICULE_STEP（600）、ISLAND_*、OCEAN_DEPTH_STOPS ——
   保持顶点数不变，精度不损失。

b) **加大世界没用**：全图适配时 zoom 自动缩小，屏幕间距不变
   （实测 1×/2×/3× 世界的屏幕 p10 都是 3.5px）。
   城市间距的硬编码阈值 `sepOf() = 12 + (3-tier)*6` 是世界单位，
   没跟着放大。

   修法（`designs/map/src/world/layout.js`）：
   `WORLD_SCALE = sqrt(n/488)` 按城市数量动态派生，间距全部乘它。
   同时 `symbolScale()` 改成按 `s = zoom/zFit` 连续缩放
   （下限 0.42），缩小时符号真正变小。

**效果**：中位最近邻 17.6 → 23.3 wu；城市之间有了可见空隙。

### 4. D 方案（manuscript）："每个章节不要全挤在同一页里，可以分页"

**根因**（实测 4,152 节点）：`makePages` 给每章**恰好一页**；
内容放不下就 `MAX_GROW` 把页高从 3400 撑到 **5800px**、字号压到
k=1.5 上限 —— cohomology 一章 873 条挤在一页（单页 929 条目）。

**修法**（`layout.js` + `layout-chapter.js`）：
- `makePages` 支持**每章多页槽位**（按内容量 `ceil(n/110)` 估算）
- `emitBody` 支持 `slice` 参数（输出 place 的某一段）
- 章页循环改为：内容按 y 切段，逐段落到该章的下一页，
  续页带页眉页脚（"卷 N · 章名（续）"）
- `util` 修正为分页后的真实填充率

**效果**：10 页 → **37 页**；每页 130–200 条（原来单页 929 条）；
`checkLayout` 31/31 通过。

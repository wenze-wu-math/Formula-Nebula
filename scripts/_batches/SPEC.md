# 关系类型判定规范（v2 · 逐条人工判定）

## 任务背景

这是「公式诗云」项目。项目把数学知识做成一个 3D 星系，公式之间用弧线相连。
**每一条连线都带一句人写的中文理由**（形如「标准猜想蕴含 Hodge 猜想」）。

现在需要你**逐条读懂这句中文理由，判定这两个公式之间到底是什么关系**，
把结果写进数据文件，让连线能按关系类型上色。

## 类型清单（只能用这 12 个 id）

| id | 中文 | 含义 | 判定信号 |
|---|---|---|---|
| `equivalent` | 等价 | 二者是同一件事的两种说法 | 「即」「正是」「等于」「=」「≅」「同构」「当且仅当」 |
| `implies` | 蕴含 | A 能推出 B | 「蕴含」「推出」「意味着」「导致」「⇒」 |
| `generalizes` | 推广与特例 | 一个是另一个的推广/特例 | 「推广」「特例」「是…的典型/原型/情形/版本」 |
| `defines` | 定义与刻画 | A 定义了 B / A 是 B 的判据 | 「定义」「刻画」「判据」「由…给出」 |
| `computes` | 计算与构造 | 用 A 能算出/造出 B | 「计算」「构造」「用来算」「实现」 |
| `property` | 性质与保持 | A 保持/满足某个性质 | 「保持」「满足」「成立」「具有」 |
| `depends` | 依赖 | 要证 B 得先有 A（推理前提） | 「依赖」「需要」「前提」「基于」「用到」 |
| `sameFamily` | 同族 | 只是归类，同属一个大类 | 「同属」「都属于」「一族」「同类」 |
| `analogy` | 类比 | 二者相似/可平行看待 | 「类比」「类似」「对应」「平行」 |
| `contrast` | 对比 | 二者不同/相反 | 「对比」「相反」「不同于」 |
| `provenance` | 同条与出处 | **编纂关系，不是数学关系**：两条其实是同一件事的两份记录 | 「主库…条目」「同一猜想」「此处是」 |
| `related` | 陈述与相关 | **兜底**：理由是一句纯粹的陈述/名词短语，**没有说出这两个东西是什么关系** | 「整环理论」「四维的拓扑刚性有独特障碍」 |

## 判定原则（重要）

1. **宁可判 `related`，不要硬凑。** 如果这句话只是在**描述一个事实**
   （「局部化保持诺特性」是在讲一条定理，不是在讲"这两个条目什么关系"），
   那它确实有意义 —— 但请判断它是否明确属于上表某一类。
   例如「局部化保持诺特性」→ `property`（"保持"是明确信号）。

2. **纯名词短语一律 `related`。** 例如「整环理论」「模空间技术中的工具」
   「表示论的技术背景」—— 这些没说关系。

3. **`property` 与 `depends` 要分清方向**：
   - 「局部化**保持**诺特性」= property（此操作不破坏该性质）
   - 「零点定理的证明**依赖**诺特性」= depends（推理需要它）

4. **`contrast` 极容易误判，务必小心。**
   中文数学术语「**差异**除子」「**差异**系数」（discrepancy 的中译）
   里的"差异"**不是**"对比"的意思。看到"差异"不要判 contrast。
   只有真正在说"两者形成对比/相反"才判 `contrast`。

5. **`provenance` 只用于编纂性说明**（"主库已有条目""同一猜想的两处陈述"）。
   它**不是**数学关系，但必须单独标出来 —— 否则用户会误以为
   "这条猜想依赖那个定理"，而真相是"这两条是同一个东西的两份记录"。

6. **`equivalent` 的符号规则**：`=` 出现在不等式（≤ ≥ < > ≠）里不算等价。

## 输出格式

**只输出一个纯文本文件**，每行一个结果，格式为：

```
<index> <type_id>
```

- `<index>` 是输入文件里每行开头的那个数字（左对齐原样，不要补零）
- `<type_id>` 必须是上表 12 个 id 之一（全小写）
- **行数必须与输入文件的行数完全一致**，顺序也必须一致
- 不要输出表头、不要输出解释、不要输出 markdown 代码块

正确样例：
```
0 related
1 defines
2 equivalent
```

## 输入文件格式

每行形如：
```
   0|nullstellensatz>ideal-variety|1|related|零点定理正是这一对应的代数根据
```

用 `|` 分成 5 段：
1. `index` — 编号（回填时用它）
2. `src>dst` — 两个公式的 id（仅供理解上下文）
3. `weight` — 权重 0~1（**仅供参考，不代表关系类型**）
4. `regex_guess` — 现有正则的猜测（**仅供参考，很不可靠，可以推翻**）
5. `label` — **中文理由，这是你要读懂的东西**

## 特别注意

第 5 段的中文里可能含 `|` 吗？不会 —— 生成时已验证标签内无 `|`。
但标签内**可能含数学符号和 Unicode**（如 `≅` `ℙ` `𝓜`），原样忽略即可，
你只需要判定类型。
